# Changelog

This file records each released version of `dicom-anon`. The format follows [Keep a Changelog 1.1.0](https://keepachangelog.com/en/1.1.0/). Versions follow [Semantic Versioning 2.0.0](https://semver.org/spec/v2.0.0.html) and the output-byte rule in [CONTRIBUTING.md](CONTRIBUTING.md#versioning). Known anomalies for each release are in [docs/known-anomalies.md](docs/known-anomalies.md).

The release workflow copies the section of the tagged version into the GitHub release notes. Before you tag a release, replace `Unreleased` in that section heading with the release date in `YYYY-MM-DD` format. The workflow refuses a heading without a date.

## [0.2.0] - Unreleased

This is the first tagged release. Version 0.1.0 was not tagged or released.

### Added

- Burned-in text censoring ([#47](https://github.com/medcognetics/dicom-anon/issues/47)): under `safe-harbor-metadata`, a deterministic heuristic decodes every frame, finds burned-in text and overwrites only the text pixels with the darkest value. It fails closed when a frame cannot be decoded, when the pixel description is unreadable or inconsistent (Bits Stored, High Bit, MONOCHROME2 with an INVERSE Presentation LUT), or when a line of text lies over tissue, faint tissue included. A censored JPEG `.50`/`.51` or JPEG-LS `.81` source gets Lossy Image Compression `01` and, when absent, its Method; censored odd-length 8-bit Pixel Data gets a padding byte. A censored object is written losslessly as native Explicit VR Little Endian without Smallest or Largest Pixel Value, and Burned In Annotation keeps its source value. `burned_in_text` and `--burned-in-text` select `auto`, `censor` or `off`. `text_over_tissue` and `--text-over-tissue` select `fail` (the default) or `leave`, which keeps text over tissue as a temporary relief and counts it, and the report records both choices and the counts, including short regions left in place.
- Wider Pixel Data decoding for the burned-in text check ([#47](https://github.com/medcognetics/dicom-anon/issues/47)): JPEG 2000 is decoded by OpenJPEG 2.5.3 in strict mode and JPEG by libjpeg-turbo 3.1.0, the builds that medcognetics/dicom-preprocessing uses. 12- and 16-bit, irreversible, multi-tile and multi-layer JPEG 2000, 12-bit DCT JPEG, and lossless JPEG with restart intervals or point transforms are now assessed instead of failing closed. Samples keep their full precision, and a decoded frame that does not match its header fails closed. A JPEG 2000 codestream with a missing tile, tile-part or packet fails closed, because OpenJPEG would reconstruct it as zero; a tier-2 packet walk checks every packet before decoding. Building needs a C compiler and CMake. `make codec-pins` checks the pins and `make test-jpeg2000-conformance` runs the ITU-T T.803 class 1 conformance codestreams.
- Pinned text-detection model for the burned-in text check ([#47](https://github.com/medcognetics/dicom-anon/issues/47)): `--burned-in-text-detector model|both` runs the PaddleOCR PP-OCRv4 mobile text detector on the CPU through ONNX Runtime 1.27.1. `dicom-text-detector install DIR`, and `install_text_detector` in the library and bindings, download both files and check their pinned SHA-256 values. Model boxes that overlap are joined. A box is censored only when its edge is background outside the anatomy, every other pixel inside is a bright glyph pixel or touches one, and it is no larger than a block of text lines; otherwise it is left in place or fails closed as text over tissue. `report-anon` refuses the model, and the release assets do not include `dicom-text-detector` yet. The default stays `heuristic`. In the `model` and `both` modes, censored pixels can differ between processor types (AVX2, AVX-512, NEON); this is an accepted exception to output determinism, and source-aware validation must run on the anonymizing host or the same processor type. The heuristic stays bit-deterministic.
- DICOM PS3.15 2026c Basic Application Level Confidentiality Profile with every metadata option column, the default `dicom-extended` preset, the `dicom` preset, and the strict `safe-harbor-metadata` policy.
- `dicom-anonymize` and `dicom-validate` commands, with candidate-only and source-aware validation.
- `report-anon` for local plaintext and PDF privacy filtering with the pinned OpenAI Privacy Filter model. Its output always requires human review.
- `dicom-to-parquet` for one-read, metadata-only Parquet export.
- Python (PyO3, abi3) and Node.js (N-API) bindings.
- `--version` for `dicom-anonymize`, `dicom-validate`, and `report-anon` prints the crate version and the source commit that the build recorded.
- A tag-triggered release workflow. It builds Linux x86_64 `dicom-anonymize` and `dicom-validate` binaries, an abi3 Python wheel, CycloneDX SBOMs of the Rust lock and of the Python and Node build-tool locks, SHA-256 checksums, and the dependency audit evidence. It attaches them to a draft GitHub release.
- This changelog and the [known anomaly list](docs/known-anomalies.md).
- Safe Harbor UID support ([#19](https://github.com/medcognetics/dicom-anon/issues/19)): `--list-required-uids` and the matching library and binding calls list each source UID that needs a map entry, with its sequence path. `--generate-uid-map PATH` assigns missing replacements from the operating-system CSPRNG and returns them in the caller map. A missing mapping error gives the tag path and never the value.
- Fail-closed descriptor option ([#20](https://github.com/medcognetics/dicom-anon/issues/20)): `--fail-on-unmapped TAG` stops when a descriptor-map miss would write a dummy value for that tag. Reports count dummy and unmapped dummy replacements by tag.
- Sequence scope for the fail-closed descriptor option ([#50](https://github.com/medcognetics/dicom-anon/issues/50)): `--fail-on-unmapped-sequence TAG` and `fail_on_unmapped_sequences` apply the guard only inside the listed sequences, at any depth below them. With a scope, a miss elsewhere is counted and gets its dummy value, and the run does not stop. This is a deliberate relaxation of a fail-closed control, so a caller that sets a scope must record it in its risk file. Without a scope, the guard is unchanged.
- Pixel-risk gates ([#18](https://github.com/medcognetics/dicom-anon/issues/18)): `--require-no-burned-in-annotation` and `--allow-sop-class UID` reject risky input. The anonymizer removes JPEG 2000 comment (COM) segments and fails closed on codestreams it cannot parse. `dicom-validate` reports `jpeg2000_comment_present` and `jpeg2000_codestream_unparseable`.
- JPEG and JPEG-LS segment removal ([#28](https://github.com/medcognetics/dicom-anon/pull/28)): the anonymizer removes COM and APPn segments from JPEG (`1.2.840.10008.1.2.4.50`, `.51`, `.57`, `.70`) and JPEG-LS (`.80`, `.81`) codestreams. It keeps one APP14 `Adobe` segment only where it changes decoded colors, and fails closed on codestreams it cannot parse or clean safely. `dicom-validate` reports `jpeg_comment_present`, `jpeg_application_segment_present`, and `jpeg_codestream_unparseable`.
- `dicom-validate` reports `encapsulated_total_length_mismatch` when Encapsulated Pixel Data Value Total Length `(7FE0,0003)` does not match the fragments ([#31](https://github.com/medcognetics/dicom-anon/pull/31)).
- A second shipped descriptor map ([#48](https://github.com/medcognetics/dicom-anon/issues/48)): `descriptor-maps/breast-imaging-references-ps3.16-2026d.json` keeps the PS3.16 2026d codes for Partial View, every Purpose of Reference context except report references, and Image Derivation.
- Mammography, breast tomosynthesis, synthesized 2D, and JPEG 2000 conformance fixtures in CI ([#21](https://github.com/medcognetics/dicom-anon/issues/21)).
- The mammography suite also runs `safe-harbor-metadata` with the shipped breast-imaging descriptor map and the fail-on-unmapped guard for the code tags, through the library and the CLI. With the map, View Code Sequence must be unchanged. Without a map, Safe Harbor mode still replaces it with `ANONYMIZED` ([#32](https://github.com/medcognetics/dicom-anon/issues/32)).
- Study-level Safe Harbor API ([#34](https://github.com/medcognetics/dicom-anon/issues/34)): `Anonymizer::anonymize_study`, Python `anonymize_study`, and Node.js `anonymizeStudy` de-identify all instances of a study with one generated UID map, run source-aware validation on each output, reject instances of a different study or patient, and fail as a whole with errors that name only the instance index and attribute paths.
- Synthetic Hologic, GE, Siemens, and Fujifilm variants of the mammography fixtures, with For Processing objects, vendor private blocks at the root and in a nested sequence, and, for tomosynthesis, in every functional group item, run through the Safe Harbor pipeline with the breast map and both pixel-risk gates ([#33](https://github.com/medcognetics/dicom-anon/issues/33)).

### Changed

- De-identification Method `(0012,0063)` now includes the crate version. The last value is `dicom-anon <version> <edition>`, or `dicom-anon <version> safe-harbor-metadata <edition>` for the Safe Harbor policy. This changes output bytes. `dicom-validate` accepts only the value that its own version writes and reports another version as `deidentification_method_version_mismatch`. Validate an output with the same version that made it.
- JPEG 2000, JPEG, and JPEG-LS Pixel Data that contains comment or application segments changes bytes: the segments are removed, and scan data and decoded samples do not change.
- The anonymizer uses less peak memory when it rewrites encapsulated Pixel Data ([#31](https://github.com/medcognetics/dicom-anon/pull/31)).
- The Cargo `repository` field and the README badge identify `medcognetics/dicom-anon`.
- Planar Configuration `(0028,0006)` is removed from images with one sample per pixel under every policy ([#40](https://github.com/medcognetics/dicom-anon/issues/40)). This changes output bytes for such inputs. Source-aware validation of an output that an earlier build made from such an input reports a mismatch for `(0028,0006)`.
- The workspace release profile no longer strips symbols, so a source build of the Python or Node.js binding loads on macOS ([#41](https://github.com/medcognetics/dicom-anon/issues/41)). The release workflow still strips the published Linux binaries and wheel.

### Fixed

- A wholly zero-length DA, DT, or TM value no longer makes de-identification fail with `invalid DA value`. A zero-length value that the profile keeps or shifts stays zero length. A value that the profile replaces with a dummy (`D`) or removes (`X`) is still replaced or removed, as in the `dicom` preset. A paired date and time where one side is empty no longer fails ([#38](https://github.com/medcognetics/dicom-anon/issues/38)). Output for input that already succeeded does not change.
